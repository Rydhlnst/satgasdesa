# QA Report: SATGAS DESA SEJOLI Production

## Summary

- Target: https://satgas.beres.io
- Health score: 5/10 — public surface is reachable, but authenticated QA is blocked.
- Pages/endpoints checked: 25, plus manifest, service worker, and favicon.
- Findings: 1 blocker, 2 minor configuration/security findings.

## Blocker

### [B-1] All supplied role accounts rejected at login

- URL: https://satgas.beres.io/login
- Reproduction: submit each supplied account: `admin@satgas.local`, `pimpinan@satgas.local`, `bendahara@satgas.local`, and `petugas@satgas.local`.
- Expected: successful redirect to `/dashboard`.
- Actual: the page remains on `/login` and displays `Invalid email or password`; the auth request returns HTTP 401.
- Impact: Pimpinan, Bendahara, Petugas, dashboard workflows, role restrictions, CRUD flows, uploads, approvals, reports, and authenticated responsive UI remain unverified.

## Minor Findings

### [m-1] Cloudflare Insights script blocked by CSP

- URL: https://satgas.beres.io/login
- Evidence: browser console reports `static.cloudflareinsights.com/beacon.min.js` blocked by `script-src 'self' 'unsafe-inline'`.
- Impact: Cloudflare analytics does not load; application login UI remains usable.

### [m-2] HSTS header missing on HTTPS response

- URL: https://satgas.beres.io/login
- Evidence: `Strict-Transport-Security` was absent while HTTPS was active.
- Impact: HTTPS enforcement is weaker for returning browsers. Configure HSTS at Coolify/reverse-proxy level after confirming all subdomains support HTTPS.

## Positive Observations

- `/` redirects unauthenticated users to `/login`.
- Public auth pages return HTTP 200: login, forgot password, reset password, verify email, unauthorized, and offline.
- All tested protected dashboard routes redirect unauthenticated users to `/login`.
- `/api/health` returns HTTP 200 with `{"status":"ok"}`.
- Unauthenticated monthly report export redirects to `/login`.
- Manifest, service worker, and favicon return HTTP 200 with appropriate content types.
- Login layout was usable at 375x812 and 1440x900 viewport sizes.
- Invalid login responses use a generic error message and do not expose account details.
